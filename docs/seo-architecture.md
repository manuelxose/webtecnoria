# SEO Architecture

## Objetivo

Dejar TecnoRia preparada para competir con una arquitectura organica sostenible en tres capas:

- demanda comercial de alta proximidad
- comparativas y contenido de decision
- evergreen MOFU/BOFU sobre software, automatizacion, IA y modernizacion

## Enlazado interno implementado

### Home

- enlaza a los 6 servicios
- enlaza a casos, metodologia y contacto
- enlaza a insights destacados para acercar trafico frio a contenido de decision

### Servicios y landings

- cada servicio enlaza a contacto
- cada landing enlaza a casos relacionados
- cada landing enlaza a articulos del mismo cluster mediante `Contenido de apoyo`
- existe relacion cruzada entre servicios adyacentes cuando la decision puede moverse a otra landing

### Blog y articulos

- el hub editorial agrupa el contenido por clusters
- cada articulo contiene CTA hacia servicio o contacto
- cada articulo muestra related content para aumentar profundidad de sesion
- la tabla de contenidos ayuda a escaneo y comprension semantica

### Casos de exito

- cada caso muestra chips hacia servicios relacionados
- la pagina actua como puente entre prueba y landing BOFU

## Enlazado interno recomendado para fase 2

- enlazar casos concretos desde articulos BOFU cuando exista mas relacion problema-solucion
- abrir breadcrumbs visuales navegables en mas paginas si el equipo quiere exponer mas jerarquia
- crear enlaces cruzados adicionales entre FAQ y landings especificas por servicio

## Oportunidades futuras de contenido

Prioridad alta:

- CRM, ERP o software propio: cuando integrar y cuando construir
- discovery tecnico: que deberia salir de una primera fase bien hecha
- automatizacion documental para finanzas y operaciones
- ROI real de automatizar procesos repetitivos
- copilotos internos para onboarding y soporte

Prioridad media:

- coste de integrar ERP, CRM y software propio
- cuando rehacer un backoffice y cuando evolucionarlo
- IA para clasificacion documental en empresas
- como definir un MVP sin sobredesarrollar

Prioridad por vertical si negocio lo valida:

- software para industria y distribucion
- automatizacion para servicios B2B
- plataformas privadas para partners o clientes
- IA aplicada a operaciones de equipos de soporte o backoffice

## Gaps semanticos detectados

- aun no hay landings por vertical o industria
- falta un cluster entero alrededor de ERP, CRM, legacy e integracion compleja
- no existe todavia una capa de contenido con datos de ROI o TCO
- los casos siguen siendo narrativos; si el negocio puede publicar cifras, el potencial SEO y de conversion sube bastante

## Reglas de crecimiento para evitar canibalizacion

- una keyword principal por pagina
- no abrir una nueva landing si la intencion cabe mejor como seccion o articulo dentro de un cluster existente
- si se crean paginas por vertical, deben cambiar problema, contexto y vocabulario, no solo duplicar la landing de servicio
- el blog debe seguir trabajando dudas, comparativas y marcos de decision; las landings deben seguir captando demanda BOFU

## Estado tecnico SEO

- titles y descriptions definidos por ruta
- canonical gestionado desde `SeoService`
- `og:image` por ruta en las paginas principales
- `og:type=article` en detalle de articulo
- schema activo para `ProfessionalService`, `WebSite`, `WebPage`, `Service`, `FAQPage`, `BreadcrumbList` y `Article` cuando aplica
- sitemap estatico mantenido
- redirecciones legacy conservadas para proteger equity previo

## Siguiente fase recomendada

- medir Search Console por cluster antes de abrir nuevas URLs
- revisar CTR de home, servicios y blog a 60-90 dias
- ampliar contenido BOFU con casos cuantificados y comparativas tecnicas
- decidir si hay una vertical comercial prioritaria para lanzar las primeras pages sectoriales
